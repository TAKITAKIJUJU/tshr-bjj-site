## 動画

FFmpeg / VP9によるWebMの2パス圧縮。PC向け720×1280、スマートフォン向け540×960。同じ映像・フレームレート・尺を保ち、対応ブラウザで軽量版を選ぶ。MP4は再圧縮せず、faststartで再生用情報を先頭に配置したフォールバックを用意。

| 対象 | 元 | 軽量版 | 削減 |
|---|---:|---:|---:|
| PC向け動画 | 7,289,011 bytes | 5,543,034 bytes | 24.0% |
| スマートフォン向け動画 | 7,289,011 bytes | 3,757,327 bytes | 48.5% |

非可逆圧縮のため動画は完全な画素一致ではない。元映像とのフレーム比較・ブラウザー表示で確認し、全編のSSIMはPC 0.9616、スマートフォン0.9579（同解像度に縮小した元との比較）。これは表示速度や主観画質の点数ではない。未対応ブラウザでは元画質のMP4を使用し、動画容量の削減効果はない。

## 画像・JavaScript・配信

- 15枚の写真に400px・800px・元解像度のWebPと `srcset/sizes` を設定。ブラウザが表示幅と画面密度に合わせて選ぶ。施設写真の拡大には元画像と同一バイト列を使用。
- 対象15枚の元ファイル合計2,273,202 bytes。400px版合計277,630 bytes、800px版858,496 bytes。全ページの通信量を示す数字ではなく、実際の選択は端末と画面密度による。
- 動画ボタンのために全翻訳辞書をクライアントへ配る処理を撤去。翻訳済みラベルをビルド時にHTMLへ埋め込む。
- 本番日本語トップのインライン＋外部JS依存ファイル合計197,645→139,995 bytes（29.2%削減）。ファイルごとのgzip推定合計75,491→54,682 bytes（27.6%削減）。実測ネットワーク転送量・Lighthouse・Core Web Vitalsの値ではない。
- 内容のハッシュ付きメディアURLに1年のimmutableキャッシュを設定。新しい素材はURLが変わるため、長期キャッシュと更新を両立。
- 動画のRange要求に206で必要なバイトだけをストリーム送信。Assets bindingがWorker内でContent-Lengthを提供しないケースに備え、生成済みのファイルサイズ表を使用。メモリ上に全動画を一括展開しない。
